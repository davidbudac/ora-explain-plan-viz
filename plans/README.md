## Verification caveats

- Every plan's code and tests were applied to a scratch copy of the repository
  and run (new tests fail before the fix and pass after; lint, typecheck and
  the full suite green). This was done per group — 001–006 together, 009–011
  and 021, 012–016 stacked in order, 007/008/017–020 together — **not** with
  all 21 stacked. Absolute test counts quoted in plans are "at `b5635d8`".
- Not run in a real browser, in SQL*Plus, or against the 19c test database.
  008 was designed so the emitted script is byte-identical for valid input
  (no database re-run needed); its stronger follow-up (a layout where no
  script line starts with hint text) does need a 19c run and is recorded in
  its maintenance notes.
- Operator steps that cannot be automated: 018 (watch the first push and the
  next tag on GitHub; workflows cannot run locally), 020 (compare the two
  `/welcome/` pages visually), 007 (confirm page views still arrive after the
  next Pages deploy), 021 (re-capture showcase media).

## Findings considered and not planned

Lower leverage — real, evidenced, left for a later round:

- Async plan loads (DB connector fetch, large file drop) land on whichever tab
  is active when they finish, and the metadata bundle attaches to the tab that
  was active at click time (`usePlanContext.tsx` `loadAndParsePlan`,
  `ConnectPanel.tsx` `loadPlan`). M, mostly connector builds.
- An open predicate swallows the following predicates when it never balances
  or a SQL*Plus page break falls inside it (`parser/predicateSection.ts`). M.
- JSON plan rows with repeated ids merge into one tree without a warning (the
  CSV path warns); a row that is its own parent overflows the stack
  (`parser/jsonPlanParser.ts`). Metadata bundles are cast, not validated: one
  malformed object silently disables four advisor rules
  (`metadata/bundle.ts`, `advisor/engine.ts`). M.
- Reload right after Share restores from the link: custom tab names (and a
  bundle dropped for size) are lost, then autosaved over.
- A link that decodes but does not parse as a plan still clears the saved
  session (adjacent to 002; noted in its maintenance notes).
- One 2.2 MB JS chunk with no lazy-loaded views; 244 KB of example text loaded
  eagerly. M; couples with the service worker's precache list.
- Compare table is not virtualised and re-renders on every context change; the
  third node-matching pass is O(unmatched A × unmatched B).
- No Content-Security-Policy in any build; the DB-connector base URL is not
  restricted to loopback; the legacy lz-string share fallback puts the plan in
  the query string; `#gz=` / ACTIVE-report inflation has no output cap.
- `HierarchicalView.tsx` and `CommandPalette.tsx` (the highest-churn UI files)
  have no tests; `ora-plan-core` behaviour tests run against `src`, not the
  built `dist` that another project vendors.
- Compare treats an adaptive join that flipped between two executions as an
  exact match (noted in 009's maintenance notes).

Rejected or deferred with a reason:

- Splitting `usePlanContext.tsx` (3,000 lines): not worth doing before the
  reducer and startup effects have characterisation tests; L effort, MED risk.
- DBMS_XPLAN Bytes column parsed 1000-based vs 1024-based, and the 240-character
  SQL*Plus `DEFINE` limit for a long manual object list in the gather script:
  plausible but unverified; both need a check on the 19c test database first.
- Lab-only account password literal in `livetests/setup/00_create_user.sql:21`
  and the scripts beside it: documented test fixture for a scratch database;
  parameterise if `livetests/` is ever advertised for shared databases.
- `public/vite.svg`: not an orphan — `scripts/capture-showcase.mjs` navigates
  to it; kept.
- Defects inside the disabled AI feature (analysis run aborts itself on start,
  AI markdown rendered with a default sanitiser config, test-case script
  details): the Run button is hard-disabled; these belong to the "ship or cut"
  decision below, not to a fix plan.
- Duplicated agent-config storage readers, provider error mapping and
  script-generator helpers: cosmetic.
- End-to-end browser tests and coverage reporting: optional; no plan.

## Direction options (not planned — maintainer's call)

- **A. AI analysis: ship or cut.** Providers, dialog, report view, test-case
  builder and the `evals/` harness exist; Run is hard-disabled and the docs say
  "Coming soon". Shipping needs the self-abort fix, output hardening and the
  key-storage decision (019). The alternative is a build flag like
  `VITE_ENABLE_DB_AGENT`. Agent handoff already covers the use case without
  key handling.
- **B. `ora-plan-core` as a published package plus a CLI.** Another project
  already vendors its `dist/`. Blockers: the global `DOMParser` for SQL Monitor
  XML under Node, `parsePlans()` returning `[]` for JSON/XML/XBI, tests that
  exercise `src` rather than `dist`.
- **C. Oracle 21c / 23ai coverage.** Every labelled fixture is 19c; the 23ai
  "SQL Analysis Report" section of DBMS_XPLAN is not parsed. `livetests/`
  already captures real reports.
- **D. "Paste from anywhere" as a tested contract.** Partly delivered by 012's
  mangling-corpus test; extend the corpus as new mangling shapes are reported.
