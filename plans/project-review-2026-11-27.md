# Oracle Plan Visualizer accuracy and desktop usability review

Reviewed v1.5.0 at `84d16c3`. The first repair should protect the saved workspace when a shared plan cannot load. The next three should address SQL Monitor timing, XBI cardinality and join input order. Each can give a user a materially different tuning conclusion from the same underlying execution.

The examples below use the app's bundled reports, checked-in Oracle captures, or small inputs that isolate a particular condition. Each finding identifies which was used. All findings have high confidence. In the effort and risk estimates, small means hours and medium means roughly a day including a regression test. Risk refers to the proposed change.

## Highest priority

| Finding | Reproduction and impact | Correction | Effort / risk |
|---|---|---|---|
| 1. An unreadable shared plan can erase a saved workspace | Start with a saved plan and annotations. Open a valid gzip share link containing a truncated SQL*Plus transcript with no plan table. The app displays a parse error, then autosave removes the existing session. Reproduced with a mounted React plan provider and its real autosaver. The recovery path handles decompression failures, but the import signals parse failure with a return value the caller ignores. [Share import](../src/hooks/usePlanContext.tsx#L1802) · [Startup recovery](../src/hooks/usePlanContext.tsx#L2033) · [Empty-session deletion](../src/lib/session.ts#L118) | Require at least one usable plan before replacing the workspace or enabling autosave of the result. Exercise both a corrupt gzip and a valid gzip with unusable contents. | Small / low |
| 2. SQL Monitor reports the wrong statement duration | Text example 17 says 13 seconds. Replay says one second, the root operation's active window. Text example 18 says 221 seconds and parses as zero because the root window is blank. XML example 27 has a target duration of 86.1 ms and 325.716 ms of accumulated elapsed time across processes. Replay calls the latter the time to return the rows. [Text parser](../packages/ora-plan-core/src/parser/sqlMonitorParser.ts#L100) · [XML parser](../packages/ora-plan-core/src/parser/sqlMonitorParser.ts#L770) · [XML capture](<../src/examples/27-sql_monitor-Partitioned Star Query.txt#L44>) | Preserve wall duration, accumulated process time and per-operation windows separately. Use wall duration for completion and before/after execution times. Preserve a missing duration as unknown. | Medium / medium |
| 3. XBI imports generate false cardinality alarms | In example 14, operation 8 returns exactly the estimated 11,500,560 rows across 22 partitions. The advisor reports a 22× error. In example 13, operation 9 produces 112,576 rows. XBI's raw total yields a 693× mismatch, while the app's existing nested-loop batching rule yields an estimate of 110,880, about 1.02×. The parser stores the printed estimate, which bypasses the shared adjustment. [XBI import](../packages/ora-plan-core/src/parser/xbiParser.ts#L546) · [Estimate derivation](../packages/ora-plan-core/src/analysis.ts#L154) · [XBI producer](https://github.com/tanelpoder/tpt-oracle/blob/master/xbi.sql) | Apply the partition and batching rules to XBI. Preserve the original printed value for inspection and retain its precision on ordinary operations. | Medium / medium |
| 4. Sorting an export changes the advisor's join recommendations | Parse bundled JSON example 12, then reverse only the array order and parse it again. The IDs, parent IDs and Oracle sibling positions are identical. The first import produces zero large-hash-build findings. The second flags operations 4, 8 and 10. The shared JSON/CSV builder appends children in file order, and the advisor interprets the first child as the build input. [Tree builder](../packages/ora-plan-core/src/parser/jsonPlanParser.ts#L90) · [Advisor rule](../packages/ora-plan-core/src/advisor/rules/hashJoinBuildSide.ts#L19) | Honor Oracle sibling position, with stable operation-ID ordering where position is absent. Compare the full tree and findings for differently sorted exports. | Small / medium |
| 5. A previous spill is reported as a spill in the last execution | Import a work area with `LAST_EXECUTION=OPTIMAL`, `LAST_TEMPSEG_SIZE=null` and a historical `MAX_TEMPSEG_SIZE` of 256 MiB. The advisor says this operation used 256 MB of temp. Oracle defines null in the last-size field as an in-memory last execution. [Import fallback](../packages/ora-plan-core/src/parser/jsonPlanParser.ts#L285) · [Spill finding](../packages/ora-plan-core/src/advisor/rules/spillToDisk.ts#L41) · [Oracle field definitions](https://docs.oracle.com/en/database/oracle/oracle-database/19/refrn/V-SQL_PLAN_STATISTICS_ALL.html) | Preserve the reporting period of each field. A historical maximum can support a separately labeled historical finding. | Small / low |
| 6. Compare pairs different sides of a self-join as exact matches | Compare two scans of `EMP` aliased `MGR` and `STAFF`. Swap their line IDs while preserving the row counts of 1 and 1,000 for the respective aliases. Compare reports exact matches and changes of +999 and −999. The exact-ID pass consumes both candidates before alias matching runs. [Matching logic](../src/lib/compare.ts#L112) | Let conflicting known aliases disqualify an exact-ID match. Match same-alias candidates before applying positional heuristics. | Small / medium |
| 7. Metadata can attach to the wrong plan or the wrong schema object | With two tabs for the same SQL ID, hashes 111 and 222, a bundle for 222 attaches to the first tab with a hash-mismatch warning. Within a bundle containing `HR.EMP` and `SALES.EMP`, an imported JSON scan with `OBJECT_OWNER=SALES` resolves to `HR.EMP` when that key comes first. These are independent lookup errors. Both can feed unrelated statistics into node details and the advisor. [Tab pairing](../src/lib/metadata/pairing.ts#L30) · [Imported object identity](../packages/ora-plan-core/src/parser/jsonPlanParser.ts#L266) · [Object lookup](../packages/ora-plan-core/src/metadata/lookup.ts#L11) | Search all SQL-ID matches for the plan hash before attaching. Preserve the owner when the format provides it, and treat an ambiguous unqualified name as unresolved. | Small for pairing, medium for ownership / medium |

## Runtime metrics and visualizations

| Finding | Reproduction and impact | Correction | Effort / risk |
|---|---|---|---|
| 8. Replay contradicts measured activity | In text example 17, Oracle assigns 50.52% of samples to sort #4 and 3.09% to scan #6. Replay names scan #6 as doing 74% of the work. The text parser discards the start offsets, and the fallback replay uses a row-count heuristic even when activity percentages are available. [Captured measurements](<../src/examples/17-sql_monitor-Exadata Cell Offload (K. Osborne).txt#L56>) · [Start offsets](../packages/ora-plan-core/src/parser/sqlMonitorParser.ts#L419) · [Replay weights](../packages/ora-plan-core/src/replay.ts#L403) | Use measured activity for the hotspot and its percentage regardless of how the animation is timed. Keep reported start offsets for timeline placement. | Medium / medium |
| 9. Flame adds overlapping active windows and calls the result elapsed time | In SQL Monitor example 21, the parser records 399.675 ms of global elapsed time and a one-second root window. The default time flame displays 4 seconds at the root and assigns one second of self time to four leaves. Core analysis deliberately leaves self time undefined for this source. [Flame rollup](../packages/ora-plan-core/src/flameLayout.ts#L41) · [Metric selection](../src/components/views/FlameView.tsx#L186) · [Tooltip](../src/components/views/FlameView.tsx#L268) | Use activity samples where available and another supported metric otherwise. Reserve self-time labels for sources that support them. | Small–medium / low |
| 10. Estimate-only imports can show a 100% runtime improvement | Compare a measured plan A with a JSON or CSV plan B that has estimates only. The row builder synthesizes zero elapsed time. Compare accepts it as a measurement and calculates −100%. [Parser default](../packages/ora-plan-core/src/parser/jsonPlanParser.ts#L125) · [Compare summary](../src/lib/compare.ts#L199) | Preserve absent runtime as undefined through import and display. Cover a measured zero separately. | Small / low |
| 11. Compare subtracts an estimated temp requirement from an actual spill | The Temp space metric picks actual usage on each side independently, falling back to the estimate. For a 100 MiB estimate in A and a 10 MiB measured spill in B, Compare reports a 90% reduction even though A has no spill measurement. [Metric mapping](../src/lib/compare.ts#L245) · [Delta calculation](../src/lib/compare.ts#L295) | Compare estimated temp and measured temp separately and suppress a delta when either side lacks the corresponding value. | Small / low |
| 12. XBI multi-selection doubles the buffer count | Select all operations in bundled XBI example 13. The report's plan total is 125,211 gets. The selection summary computes 250,422. XBI's root is a total, while non-root I/O is already exclusive. Subtracting direct children as if every row were cumulative leaves the root total in the sum a second time. [Selection aggregation](../src/lib/selectionStats.ts#L42) · [Captured totals](<../src/examples/13-xbi-XBI TPC-DS Query.txt#L11>) · [XBI column definitions](https://github.com/tanelpoder/tpt-oracle/blob/master/xbi.sql) | Normalize XBI I/O at import or handle its root-total and per-operation semantics explicitly in aggregation. Check both full-tree and partial selections. | Small–medium / low |
| 13. Measured Replay announces the first row after its own completion time | In the Window Sort Spill example, the root's first-row timestamp gives an offset of +9 seconds. Replay interpolates a one-row output curve and announces the first row at 10.0 seconds. Its closing caption says the row was returned in 8.5 seconds. [Captured timestamp](<../src/examples/23-sql_monitor-Window Sort Spill.txt#L202>) · [First-row chapter](../packages/ora-plan-core/src/replay.ts#L866) | Use the recorded first-row offset and preserve the precision of the source timestamp. Label an inferred time when the timestamp is absent. | Small / low |
| 14. More work is colored as an improvement in Compare | Raising Starts from 1 to 1,000 produces a green improvement in the per-operation delta. The same rule treats increases in estimated rows, actual rows and bytes as improvements. Each can increase or decrease depending on plan shape and result size. [Delta tone](../src/components/views/CompareView.tsx#L31) · [Metric policy](../src/lib/compare.ts#L268) | Give these counts neutral deltas unless the app has enough context for a performance verdict. | Small / low |

## Verification and repair order

`npm run lint`, `npm run typecheck` and all 2,123 tests in 169 files passed. The invalid-link check exercised React session persistence in jsdom. The numeric reproductions used the project parsers, advisor, comparison, replay and layout functions. The baseline verification finding comes from the generated SQL predicate. This review did not include a live Oracle connection, manual desktop browser testing, the external connector service, mobile layouts or accessibility.

Protect autosave first. Fix timing and cardinality at import before revising Replay, Flame and Compare. Keep the unmodified examples as regression inputs, and use reordered exports and paginated copies to test that presentation changes preserve the underlying plan.
