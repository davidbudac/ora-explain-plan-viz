Feature tour

Built around how you actually tune a plan

01

Interactive plan tree

The plan renders as a real tree, laid out with a custom algorithm (Dagre as fallback), not a scrollable text block. Click any node to see its full attributes, predicates, and cardinality analysis. Cmd/Ctrl-click for multi-select with aggregated stats. Arrow keys move between parent, child, and sibling nodes.

Try this live →
02

Hotspot detection & runtime stats

When SQL Monitor data is available, every node shows A-Rows, E-Rows, A-Time, and Starts. The node with the highest A-Time gets a red ring and a "Hotspot" badge automatically. When nothing is selected, a summary panel lists the top 5 nodes by A-Time, cost, and worst cardinality mismatch. Click any entry to jump straight to it.

Try this live →
03

Cardinality mismatch analysis

Compares the optimizer's E-Rows estimate against the actual A-Rows for every node and flags the divergence with severity badges (warn at 3x, bad at 10x). A dedicated filter slider hides everything except nodes that exceed a mismatch threshold you set, so stale statistics and bad selectivity guesses surface right away.

Try this live →
04

Sankey data-flow view

The same plan rendered as a D3 Sankey diagram, where band width encodes volume flowing between operations. Toggle the metric (rows, cost, A-Rows, or A-Time) to see which step is moving the most data or burning the most time.

Try this live →
05

Plan comparison

Load two plans side by side: before and after an index change, a hint, or a statistics refresh. A 3-pass node matcher lines up equivalent steps across both plans and computes deltas across 9 metrics — cost, rows, bytes, A-Rows, A-Time, self time, starts, temp space, and memory — with improvement or regression flagged on each. The Tree and Tabular tabs also switch to side-by-side dual-pane variants when two plans are loaded.

Try this live →
06

Annotations & sharing

Attach timestamped notes to any node, mark it with one of 7 highlight colors, or group several nodes under a named label. Export the annotated plan as a JSON file, load it back later, or hand it to a teammate. Re-importing validates it against the original plan.

Try this live →
07

Flame graph

Where does the time (or cost) actually go? The plan rendered as a flame graph, with bars sized by each operation's self value. Toggle the metric between Cost, A-Time, and A-Rows, and click any bar to zoom into that subtree.

Try this live →
08

Execution timeline & experimental views

From a SQL Monitor XML report, a Gantt of when each operation was actually active, colored by ASH wait class. The Experimental tab also holds an E-Rows vs A-Rows calibration scatter, a wasted-work waterfall (rows read vs returned), an estimate→actual icicle morph, and per-line wait-class composition.

And more

The rest of the toolbox

Plan advisor

Ten heuristic rules — cardinality mismatch, implicit conversion, cartesian joins, spills to disk, missed partition pruning, stale stats, and more — surfaced per node and as a ranked list.

Schema metadata

Attach table, index, and column stats gathered by a generated SQL script. Objects show inline badges in the plan, and a dedicated Metadata explorer browses the whole bundle.

SQL Plan Baseline script

Generates a ready-to-run DBMS_SPM script that pins the loaded plan — from the cursor cache, AWR, or a SQL Tuning Set — with pre-checks and verification queries.

Client report export

Package the plan, your notes and highlights, and all derived findings into one self-contained HTML document to hand to a client — or print it to PDF.

Share via URL

Bake the whole plan into a gzip-compressed link — from the app, or straight from the database with the bundled plan_to_url.sql script.

Make it yours

Light and dark themes, five app palettes, eight node color schemes, Minimal-to-Detailed density presets, a focus mode, and a Cmd/Ctrl-K command palette for all of it.

Input formats

Paste what you already have

No conversion step. Copy the output straight from SQL*Plus or SQL Developer, paste it in, and the format is detected automatically.

DBMS_XPLAN

Standard optimizer plan: rows, bytes, cost, predicates.

text

--------------------------------------------------
| Id | Operation           | Name  | Rows | Cost |
--------------------------------------------------
|  0 | SELECT STATEMENT    |       | 1000 |15234 |
|  1 |  SORT ORDER BY      |       | 1000 |15234 |
|* 2 |   HASH JOIN         |       | 1000 |15210 |
